Compatibility & privacy

The secret is encoded as SQL nvarchar (UTF-16LE), hashed with SHA-256, then used as the HMAC-SHA256 key for patient| plus your exact value in UTF-8. Output is 64 uppercase hexadecimal characters. Nothing is trimmed, case-folded or converted to a number.

Plain positive decimal IDs such as 12345 still match your SQL export with @EncryptPatientIDs = 1. Leading zeroes, spaces, signs and arbitrary text now have their own keys; the original SQL converts numeric IDs to canonical decimal text. Non-ASCII text also depends on the SQL database’s varchar encoding.

An empty single value can be hashed. Empty CSV cells are left blank so missing IDs are not assigned a shared linkage key. Use original values, not already-generated keys.

These are pseudonyms, not anonymous data. Protect the secret: anyone who knows it can test possible IDs. Use separate secrets for projects that should not be linked. Other identifying fields can still reveal a person.

The page does not save inputs or send them to a server. Clear all removes inputs and results from the page, but cannot erase clipboard contents or downloaded files. Use a trusted browser and device.
